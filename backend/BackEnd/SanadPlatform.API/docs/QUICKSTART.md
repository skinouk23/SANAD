# Quick Start Guide

## Prerequisites
- ✅ .NET 8.0 SDK installed
- ✅ SQL Server 2019 or later (or SQL Server Express)
- ✅ Visual Studio 2022 or VS Code with C# extension
- ✅ Git

## 🚀 5-Minute Setup

### Step 1: Navigate to Project
```bash
cd BackEnd/SanadPlatform.API
```

### Step 2: Restore Dependencies
```bash
dotnet restore
```

### Step 3: Configure Database Connection
Edit `appsettings.json`:
```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Server=.;Database=SanadPlatformDb;Trusted_Connection=true;TrustServerCertificate=true;",
    "LoggingDatabase": "Server=.;Database=SanadPlatformLogsDb;Trusted_Connection=true;TrustServerCertificate=true;"
  }
}
```

> For LocalDB: `Server=(localdb)\\mssqllocaldb;Database=SanadPlatformDb;`

### Step 4: Create & Migrate Database
```bash
dotnet ef database update
```

This will create both databases with all tables.

### Step 5: Run the Application
```bash
dotnet run
```

API will be available at:
- **HTTP**: `http://localhost:5000`
- **HTTPS**: `https://localhost:5001`
- **Swagger UI**: `https://localhost:5001/swagger`

## 🧪 Test the API

### 1. Register a User
```bash
POST https://localhost:5001/api/auth/register
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "SecurePass123!",
  "confirmPassword": "SecurePass123!",
  "firstName": "John",
  "lastName": "Doe",
  "phoneNumber": "+1234567890"
}
```

### 2. Login
```bash
POST https://localhost:5001/api/auth/login
Content-Type: application/json

{
  "email": "user@example.com",
  "password": "SecurePass123!"
}
```

Response will include JWT token:
```json
{
  "success": true,
  "message": "Login successful",
  "data": {
    "userId": "...",
    "email": "user@example.com",
    "firstName": "John",
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "role": "User",
    "expiresIn": 3600
  }
}
```

### 3. Use Token in Requests
Add to all authenticated requests:
```
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 4. Get User Profile
```bash
GET https://localhost:5001/api/auth/profile
Authorization: Bearer {token}
```

## 🛠️ Development

### Add New Feature (Vertical Slice)
1. Create folder: `Features/YourFeature/`
2. Create subdirectories: `Controllers`, `DTOs`, `Entities`, `Repository`, `Repositories`, `Services`, `Commands`, `Queries`, `Validators`
3. Implement entity in `SanadDbContext.cs`
4. Register in `Program.cs`
5. Run migration: `dotnet ef migrations add AddYourFeature`

### Format Code
```bash
dotnet format
```

### View Migrations
```bash
dotnet ef migrations list
```

### Revert Migration
```bash
dotnet ef database update PreviousMigration
dotnet ef migrations remove
```

## 📝 Logging Levels

Configure in `appsettings.json`:
```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft.AspNetCore": "Warning"
    }
  }
}
```

- **Trace**: Very detailed, diagnostic info
- **Debug**: Debugging info
- **Information**: Normal operation milestones ← Default
- **Warning**: Unexpected situations (login failures)
- **Error**: Something failed
- **Critical**: Service cannot continue
- **None**: No logging

## 🐛 Troubleshooting

### Issue: "Cannot connect to database"
**Solution**: 
- Check SQL Server is running
- Verify connection string in `appsettings.json`
- Check database exists: `SELECT * FROM sys.databases`

### Issue: "Migrations pending"
**Solution**:
```bash
dotnet ef database update
```

### Issue: "Port already in use"
**Solution**: Edit `Properties/launchSettings.json` and change port numbers

### Issue: "JWT token invalid"
**Solution**:
- Ensure token hasn't expired
- Check `Authorization: Bearer {token}` format
- Verify token was generated by this API

## 📚 Available Endpoints

### Authentication
| Method | Endpoint | Auth | Purpose |
|--------|----------|------|---------|
| POST | /api/auth/register | No | Register new user |
| POST | /api/auth/login | No | Login user |
| GET | /api/auth/profile | Yes | Get user profile |

### Providers
| Method | Endpoint | Auth | Purpose |
|--------|----------|------|---------|
| GET | /api/providers/active | No | Get active providers |
| GET | /api/providers/{id} | No | Get provider by ID |
| GET | /api/providers/country/{country} | No | Get providers by country |
| POST | /api/providers | Yes (Admin) | Create provider |
| PUT | /api/providers/{id} | Yes (Admin) | Update provider |
| DELETE | /api/providers/{id} | Yes (Admin) | Delete provider |

### Health
| Method | Endpoint | Auth | Purpose |
|--------|----------|------|---------|
| GET | /api/health/live | No | Liveness check |
| GET | /api/health/ready | No | Readiness check |
| GET | /api/health/version | No | API version |

## 🎯 Common Tasks

### Create a Provider (as Admin)
First, update the user role in database:
```sql
UPDATE Users SET Role = 'Admin' WHERE Id = 'your-user-id'
```

Then:
```bash
POST https://localhost:5001/api/providers
Authorization: Bearer {admin-token}
Content-Type: application/json

{
  "name": "Dr. Smith Clinic",
  "email": "clinic@example.com",
  "phoneNumber": "+1234567890",
  "description": "Professional healthcare provider",
  "address": "123 Main St",
  "city": "New York",
  "country": "Tunisia"
}
```

### Clear Cache
The application caches active providers for 1 hour. To clear:
- Restart the application
- Or update a provider (automatic cache invalidation)

## 🤝 Integration with Frontend

### Add API URL to Frontend
In frontend `.env.local`:
```
VITE_API_URL=https://localhost:5001
```

### Store Token
After login, store token in localStorage:
```javascript
localStorage.setItem('authToken', response.data.token);
```

### Attach Token to Requests
```javascript
const response = await fetch('https://localhost:5001/api/providers/active', {
  headers: {
    'Authorization': `Bearer ${localStorage.getItem('authToken')}`
  }
});
```
